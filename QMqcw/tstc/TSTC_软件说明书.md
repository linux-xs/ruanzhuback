### 1.2 开发目的

为一款面向手机的网页版休闲互动应用提供完整的服务端与前端实现。用户在移动浏览器中管理自己的车辆与车位，把空闲车辆派往其他用户的车位按分钟获取收益，并在"锁定期—观察期—争夺期—期满"的时间轴规则下，与车位主人围绕"召回""贴条""幸运卡即时结算"做出取舍，形成轻量的社交博弈。全部资产计算在服务端完成，客户端只负责展示与操作。

### 1.3 主要功能概要

1. **账号与资产体系**：自动建号、五位玩家短号、等级与经验、金币、幸运卡、每日额度的统一管理。
2. **车辆管理**：一百级车型图鉴、按等级解锁购买、按买入价 85% 回收出售、车库额度随等级增长（上限 10 辆）。
3. **车位管理**：车位数量随等级解锁（上限 10 个），车位格子单调状态流转，占用与释放均由条件更新保证互斥。
4. **一套四阶段时间轴**：车辆停入他人车位后依次进入绝对锁定期（0–59 分钟）、逃生观察期（60–119 分钟）、争夺期（120 分钟起）、期满（满 8 小时），不同阶段开放不同操作。
5. **四条结算路径**：主动召回（车主拿 90%）、贴条结算（车主 80% / 车位主人 20%）、期满结算（车主 100%）、幸运卡即时结算（按满额 100%）。
6. **动态倍率**：按停车方与车位主人的等级差给出 1 倍 / 1.5 倍 / 2 倍三档倍率，全部以整数比例运算。
7. **通讯录**：按玩家短号搜索名片、单向好友与仇人关系、仇恨值排序、24 小时访客动态、推荐玩家列表。
8. **签到与幸运卡**：普通签到免费领金币，幸运卡签到消耗 1 张领高额金币与经验；幸运卡通过观看激励内容领取，每日上限 10 张。
9. **生态维持任务**：内置 100 个系统账号，由后台巡检任务定期派出车辆、贴条、按余额升级，保证任何时刻都有车位可停。

### 1.4 技术特点

- **服务端**：Go 1.22 及以上版本，路由使用标准库 `net/http` 的方法化路由模式，不引入 Web 框架；数据访问使用 `database/sql` 与 MySQL 8.0 驱动，全部 SQL 参数化。
- **业务分层**：领域规则（`internal/gameplay`）、业务编排（`internal/service`）、数据访问（`internal/repo`）、接口层（`internal/api`）四层分离，规则调整只改领域层，不牵动接口。
- **金额精算**：金币统一用 `int64` 整数表示，倍率用有理数（分子/分母）表达，分成用千分比切分并保证"两份之和恒等于总额"，杜绝浮点误差与出现 1 枚金币的挂账差额。
- **并发安全**：把车派出、把车位占住都通过"带前置状态的条件更新"完成，影响行数为 0 即判定为被抢占；租约结算同样带 `status = 0` 前置条件，同一段租约只会被结算一次。
- **前端**：原生 HTML、CSS、JavaScript，无框架、无构建步骤，按核心层（接口/格式化/状态中心）与视图层拆分文件，移动端自适应。
- **可复现材料**：源程序鉴别材料由脚本从同一份源码生成，输出字节级一致，可反复复算比对。

## 三、安装与启动

### 3.1 目录规划

| 路径 | 用途 |
|---|---|
| `cmd/server/` | 服务端启动入口 |
| `internal/` | 服务端内部实现（领域、服务、仓储、接口、巡检、配置） |
| `sql/` | 数据库结构脚本与初始数据脚本 |
| `web/` | 前端页面与静态资源 |
| `conf/setting.conf` | 运行配置 |
| `tools/make_material.py` | 源程序鉴别材料生成脚本（不参与运行） |

### 3.2 数据库初始化

```bash
mysql -u root -p < sql/schema.sql
mysql -u root -p < sql/seed.sql
```

第一条建立库 `tstc` 与 8 张表，第二条写入 100 个系统账号、1 个演示账号及其车辆与车位。

### 3.3 修改配置

编辑 `conf/setting.conf`，至少修改数据库口令：

```
db:
  host: 127.0.0.1
  port: 3306
  user: tstc
  secret: 你的数据库口令
  schema: tstc
```

数据库口令也可以用环境变量 `TSTC_DB_SECRET` 覆盖，容器部署时不必写进文件。

### 3.4 启动

```bash
go build -o tstc-server ./cmd/server
./tstc-server -c conf/setting.conf -web web
```

启动成功后日志输出：

```
偷偷停个车 V1.0 已启动，监听 :8080
机器人巡检已启动，间隔 10m0s
```

浏览器访问 `http://服务器地址:8080/` 即可进入应用。

### 3.5 停止

向进程发送 `Ctrl+C` 或 `SIGTERM`，服务会在 8 秒内处理完在途请求后退出；期间不落库半成品数据。

### 4.1 页面地图

| 页面 | 入口 | 主要内容 |
|---|---|---|
| 首页 | 底部导航「首页」 | 顶部资产栏、每日签到、经验进度、我的车概览、我的车位概览、最近动态 |
| 车库 | 底部导航「车库」 | 每辆车一张卡片，按状态给出「一键停车」「选人停车」「召回」「幸运卡秒结」「卖掉」 |
| 车位 | 底部导航「车位」 | 我的车位格子、停在我家的车与贴条预览 |

- **状态标签**：车辆卡片右上角显示「空闲」或「停车中」，停在外面的车卡片会展开阶段进度条与累计收益。

## 五、功能说明与操作步骤

### 5.1 账号与首次进入

1. 打开页面，客户端读取本地缓存的玩家短号；没有缓存时自动向服务端申请建号。
2. 服务端生成五位短号，发放一辆 1 级「破旧拖拉机」、8,000 金币、1 张幸运卡与 1 个车位。
3. 建号成功后页面顶部显示昵称、等级与短号，其余区域填充资产。

**【界面要素】** 首次进入后的完整首页（含顶部资产栏与签到面板）。

### 5.2 每日签到

1. 首页「每日签到」面板提供两个按钮。
2. 点「普通签到」：立即获得 5,000 金币。
3. 点「幸运卡签到」：消耗 1 张幸运卡，获得 50,000 金币与 20 点经验；幸运卡为 0 时按钮置灰并提示去首页获取。
4. 签到成功后弹出回执，显示方式、金币、经验、当前等级与连续签到天数；当天已签到后两个按钮均置灰。

**【界面要素】** 签到成功弹窗（含金币、经验、连续天数三行）。

### 5.3 幸运卡获取

1. 点顶部资产栏「获取」。
2. 服务端校验当日额度（每日 10 张），通过则幸运卡 +1，并返回今日剩余次数。
3. 额度用尽时按钮显示「今日已满」，点击提示明天再来。

**【界面要素】** 顶部资产栏「获取」按钮点击后，幸运卡数字从 5 变为 6 的界面。

### 5.4 车辆购买与出售

1. 进入「图鉴」，列表按等级从小到大排列，显示价格、每小时产出、满额收入与回收价。
2. 未解锁车型的按钮显示「等级不够」，金币不足显示「金币不够」，可购买的显示「购买」。
3. 点「购买」后服务端依次校验等级、车库额度、余额，通过则扣款并落库；余额不足或额度已满会给出对应提示。
4. 在「车库」点某辆空闲车的「卖掉」，按买入价 85% 回收，车辆立即从车库消失。

**【界面要素】** 图鉴列表中「购买」按钮与「等级不够」按钮同屏可见的一段。

### 5.5 一键停车与选人停车

1. 在「车库」找到状态为「空闲」的车。
2. 点「一键停车」：服务端从全服空闲车位中随机锁一个，把车停进去，弹出停车成功弹窗，显示车位主人昵称与等级、车位号、倍率与满额收入。
3. 点「选人停车」：输入对方五位短号，服务端锁定对方名下的第一个空车位；对方车位已满或短号不存在时有明确提示。
4. 停车动作在一个事务内完成「锁车 → 锁车位 → 建租约 → 记动态」，任一步失败整体回滚。

**【界面要素】** 停车成功弹窗（含倍率与满额收入两行）。

### 5.6 四阶段时间轴

停车期间，车辆卡片按停放时长切换阶段，阶段决定可用操作：

| 阶段 | 时间范围 | 车主可做 | 车位主人可做 |
|---|---|---|---|
| 绝对锁定期 | 0–59 分钟 | 幸运卡秒结 | 无 |
| 逃生观察期 | 60–119 分钟 | 召回、幸运卡秒结 | 无 |
| 争夺期 | 120 分钟起 | 召回、幸运卡秒结 | 贴条 |
| 期满 | 满 8 小时 | 自动结算 | 自动结算 |

**【界面要素】** 车库中一辆处于「争夺期」的车卡片，展开的阶段进度条与阶段说明文字。

### 5.7 召回与幸运卡秒结

1. 在「车库」点停车中的车卡片。
2. 点「召回」：按当前累计收益的 90% 结算给车主，车位立即变空，车辆回到空闲。
3. 点「幸运卡秒结」：消耗 1 张幸运卡，按当前倍率直接拿满 8 小时收益，不受已停时长影响。
4. 两种操作都会弹出结算弹窗，列出停放分钟数、毛收益、本人所得、对方所得与获得经验。

**【界面要素】** 召回成功弹窗（含停放分钟数与所得金币）。

### 5.8 我的车位与贴条

1. 进入「车位」，上方是车位格子（空着为虚线框，被占为高亮），下方是停在我家车位上车辆的卡片。
2. 卡片上显示车主昵称与等级、倍率、已停时长、累计收益，以及"贴条后双方各拿多少"的预览。
3. 进入争夺期后「贴条」按钮可点：车主拿 80%，车位主人拿 20%，车辆被强制开走，车位释放。
4. 未到争夺期时按钮置灰，并提示还要等多久。

**【界面要素】** 车位页中一张可贴条的外来车卡片（按钮为可点状态，预览两行金额可见）。

### 5.9 通讯录

1. **按号找人**：输入五位短号点「找人」，弹出名片，显示昵称、等级、车位空闲数、去停能拿几倍，以及「加好友」「标仇人」「去停车」三个按钮。
2. **好友**：单向关注，列表按「有空位 + 等级高」排序，方便挑高倍率车位。
3. **仇人**：被贴条时自动收录，按仇恨值排序，卡片显示"结仇 N 次"。
4. **动态**：最近 24 小时的停车、离开、贴条记录，附时间。
5. **推荐**：等级较高且有空位的其他用户，用于快速找车位。

**【界面要素】** 搜索名片（含三个按钮）与下方好友列表同屏。

### 5.10 车辆图鉴

1. 进入「图鉴」，顶部提示"当前等级 Lv.N，可购买到 Lv.M"。
2. 列表默认展示到当前可购买等级后 3 级，已拥有的车型标注「已拥有」。
3. 点「购买」直接下单，成功后有轻提示与余额刷新。

**【界面要素】** 图鉴页顶部提示文字与列表前三行。

### 5.11 后台生态巡检（无界面）

1. 服务启动后按配置间隔（默认 10 分钟）触发一次巡检。
2. 每轮从 100 个系统账号中随机抽 60 个，依次执行：给停满 3 小时的租约贴条、把空闲车辆停进全服空位、余额够时卖旧买新。
3. 巡检与用户操作走完全相同的服务入口，因此同样受时间轴与额度规则约束。
4. 期满结算由服务端每分钟扫描一次，与用户是否在线无关。

**【界面要素】** 本节无界面要素，由后台定时任务执行。

### 6.2 核心算法模块

| 模块 | 实现要点 |
|---|---|
| 阶段判定 | 时间轴以三个时长阈值表达（1 小时 / 1 小时 / 6 小时），`StageOf` 逐段比较得出阶段；权限用位图 `ActSet` 表达，规则集中在 `stageActs` 一张表 |
| 倍率报价 | 以等级差的正负三分支给出有理数倍率，避免 1.5 进入浮点；倍率文案与说明同源生成 |
| 金额折算 | `Coin.PerMinute` 用"每小时收益 × 分钟数 ÷ 60"一次取整；`Coin.Split` 用千分比切分并把余数归第一位，保证总额守恒 |
| 结算裁定 | `Policy.Adjudicate` 按"谁发起 + 什么方式 + 当前阶段"三重校验后产出结算单，包含毛收益、双方所得、原因与播报文案 |
| 抢占互斥 | 派车与占位都是 `UPDATE ... WHERE 状态 = 期望值`，影响行数为 0 即刻返回"手慢了"；结算 `UPDATE ... WHERE status = 0` 保证只结一次 |
| 图鉴生成 | 19 个锚点数据，锚点之间价格按等比插值、产出按等差插值，最终对齐到 10 的整数倍，逐级单调递增 |
| 生态巡检 | 每轮 `rand.Perm` 抽样 60 个账号，依次贴条、发车、换车，全部复用用户侧服务入口 |
| 期满扫描 | 每分钟取"停入时间 ≤ 当前时间 − 总时长"且未结算的租约，逐条独立事务结账，避免大批行锁 |
